# 3. Visión general del producto

Se quiere construir un software para empresas de El Salvador que permita gestionar internamente sus obligaciones relacionadas con la Ley para la Protección de Datos Personales.

La plataforma NO será un servicio de outsourcing de privacidad.

La empresa que compra o licencia el sistema será responsable de:

- designar a una o varias personas internas;
- completar la información requerida;
- tomar decisiones legales;
- aprobar documentos;
- atender solicitudes;
- ejecutar acciones;
- mantener actualizada su información;
- decidir cuándo necesita asesoría jurídica externa.

El proveedor del software NO pretende actuar como:

- Delegado de Protección de Datos del cliente;
- abogado del cliente;
- auditor jurídico externo;
- responsable del tratamiento del cliente;
- operador humano de las solicitudes ARCO-POL del cliente;
- consultor permanente de privacidad.

La propuesta de valor principal es:

> Convertir las obligaciones de protección de datos de una empresa en procesos guiados, tareas, plazos, responsables, evidencias, alertas, documentos y registros auditables.

La empresa aporta a las personas responsables.

El software aporta:

- estructura;
- conocimiento operativo;
- seguimiento;
- recordatorios;
- workflows;
- trazabilidad;
- evidencia;
- documentación;
- control;
- automatización.

# 4. Hipótesis de negocio

La hipótesis principal es que muchas empresas de El Salvador:

- tienen que cumplir normativa de protección de datos;
- no cuentan con un departamento especializado en privacidad;
- no quieren contratar permanentemente a una persona adicional únicamente para gestionar estas obligaciones;
- actualmente pueden estar utilizando Excel, Word, correos, carpetas compartidas y procesos manuales;
- podrían preferir utilizar una herramienta que guíe a una persona ya existente dentro de la organización.

La plataforma debería permitir que una empresa designe internamente a personas de áreas como:

- Administración;
- Legal;
- Compliance;
- Recursos Humanos;
- Tecnología;
- Seguridad;
- Riesgos;
- Marketing;
- Auditoría;
- Operaciones.

La plataforma debe permitir que una misma persona tenga varios roles si la empresa es pequeña.

También debe permitir separación de funciones en organizaciones medianas y grandes.

# 7. Marco regulatorio inicial conocido

IMPORTANTE:

La siguiente información es contexto inicial y NO debe considerarse automáticamente correcta o vigente.

Antes de diseñar requisitos legales, debes verificar las fuentes oficiales más recientes.

El proyecto parte del conocimiento de que en El Salvador existe la:

**Ley para la Protección de Datos Personales — Decreto Legislativo n.º 144.**

Se ha identificado como contexto previo que:

- fue publicada en noviembre de 2024;
- regula el tratamiento de datos personales;
- reconoce derechos conocidos como ARCO-POL;
- existen obligaciones relacionadas con seguridad;
- existen obligaciones relacionadas con avisos de privacidad;
- existen obligaciones relacionadas con responsables y encargados;
- existen obligaciones relacionadas con transferencias internacionales;
- existen obligaciones relacionadas con incidentes de seguridad;
- existen políticas y lineamientos emitidos por la autoridad;
- existen formularios oficiales para derechos ARCO-POL;
- existe un régimen sancionador;
- se han producido reformas posteriores;
- en septiembre de 2026 fue aprobada una reforma relacionada con la figura del Delegado de Protección de Datos para empresas privadas.

Debes investigar el estado jurídico ACTUAL antes de diseñar el sistema.
